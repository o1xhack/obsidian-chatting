# Phase 4: PR #39 — remote MCP (0.8.0)

Scope: author commit `5be1624d1493435bf08b3778e5ab4c80acd8ac67`, merged with ancestry preserved on `codex/phase-4-mcp-080`, based on main `c2c87fb`. PRs #40–46 are excluded. Chat persistence remains version 3.

## Review fixes

- Empty token input now explicitly clears SecretStorage; an unavailable/unloaded token is still left alone. Duplicate/unsafe server IDs are rejected on load. New servers have distinct random IDs and start disabled. URL userinfo/fragments are refused so credentials belong in the token field.
- Native replay is bound to a hash of the server ID, endpoint and authorization. No token is saved in that metadata. OpenAI cursor reuse also requires the same MCP configuration; disabling a server works in a live conversation, without importing history first.
- Visible tool results use the same shared newest-first budget at callback emission, in live/folded UI rows, and on save/restore; older local and MCP rows release their payloads while preserving row identities.
- Remote result text shares the 200,000-character local tool allowance, with a 100,000-character per-result limit. Multi-part results cannot multiply that limit. Exhausted results have one marker, and exact block boundaries still disclose omissions. Structured OpenAI errors share the output allowance and preserve their API error shape. Oversized OpenAI tool catalogs are replaced with a rediscovery notice, preserving complete schemas only when they fit the shared allowance. Non-text Anthropic MCP result payloads are omitted with text markers instead of bypassing attachment budgets.
- First review findings fixed: conversation-wide Anthropic call IDs now remove paused-call results across messages when configuration changes; failed OpenAI Responses preserve, display and save remote receipts, with portable summaries when changing provider. Receipts also stay in native text after server revocation, including when only part of a replay is removed.
- Mobile server IDs use getRandomValues without requiring randomUUID/SubtleCrypto. MCP rows wrap in narrow desktop windows as well as on phones.
- Failed calls with no error payload are shown as failures. Pending and incomplete server calls are not reported as successfully completed. Anthropic pause-turn continuations can match a result with a call in retained history.
- Truncated responses retain completed remote receipts while dropping partial local calls. Failed Responses containing MCP calls are not automatically retried, and the user is told external changes may already have happened.
- Server changes take effect on the next request of a running turn; already-sent remote calls cannot be recalled. The guide explains context sharing, device-local tokens, automatic execution and the scope of vault Undo.
