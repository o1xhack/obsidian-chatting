# Phase 7: voice integration (PR #46)

Scope: the contributor's voice commit `bafa36e559a78a39135c4b82154e4b6b6c0549ad`, merged with 0.10.0 main `2fc7b57` while preserving ancestry. This stage prepares the existing PR for merge; it does not merge, tag or publish a release. Plugin identity, minimum Obsidian version and saved chat format remain unchanged.

## Behavior and integration fixes

Voice uses the existing ChatGPT sign-in to create a Codex WebRTC call. A conversational frontend delegates work to the selected chat provider; vault actions and their results remain ordinary chat turns. This backend is distinct from OpenAI's documented API-key Live service. Account access and limits are not inferred from public API pricing.

The integration retains main's MCP checkpoint/replay protections, portable compaction, per-chat storage, draft preservation and selection fingerprints. Voice requests use the selection displayed in the composer. Refusal before dispatch reports failure to the voice controller without replacing the unsent typed composer or clipping earlier user rows. Manual compaction is never stopped merely because voice requested work.

Delegation IDs dispatch at most once per call, including events delivered after a completed turn. Similar but longer requests are not treated as duplicates of already-steered words. A spoken ask_user ends at its question; later tools in the same batch retain cancellation results until the user answers. Stop reports stopped rather than reading an intermediate response as a final success. Preflight failures and thrown errors cannot claim the requested work succeeded.

Hold mode is muted before SDP exchange. Ending a call disables the microphone and pauses output immediately, ignores late delegation events and prevents re-enabling tracks. A data-channel send failure during closing still releases all media resources. Startup permission and call-creation waits are bounded and cancel promptly; a microphone granted after timeout/cancellation is released. Hold-to-talk also releases on element/window blur and lost pointer capture. Signing out ends an active call.

Completed user transcript events now enter steering even when the voice frontend acknowledges without delegating. Consumed original utterances do not reappear after a paraphrased delegation. Speech/progress chunks retain exact separators. Capability diagnostics bound fetch, streaming readers and model-list waits, abort/cancel stalled probes and continue to later checks. Eight regression tests cover these three Codex P2 findings, including both terminal-event orders and ignored-abort WebViews.

Automatic reconnection now keeps the running controller and turn hooks until delegated work (including late additions) finishes. Its transport closes immediately; the replacement call is seeded with the saved result without rerunning work. A lost background connection no longer marks the task owner ended. Open user transcript fragments are drained at task completion, with late terminal events deduplicated. A data channel closed before opening releases startup resources immediately. Seven additional regressions cover healthy/lost mobile reconnection, completion ordering both pre-open close timings, and failed/stopped outcome handoff without substituting an older answer.

Late steering now retains structured voice turns from the agent queue through the view and controller into a new turn. The existing pendingMessages string format remains unchanged; its saved/typed fallback includes the formatted context, while a transient per-conversation buffer retains roles for active voice. A spoken ask_user leaves additions queued because no next provider step will consume them. Four regressions cover final-response, clarification, pre-loop and ended-call fallback orderings.

Fallback additions now wait through a voice clarification, including Chinese question punctuation and a backend task that finishes while awaiting the reply. The eventual addition carries both the clarification and answer; a timer racing the final step leaves a structured next-turn item. The first accepted voice turn consumes its selection pill, while refusal before dispatch retains it. A prefix delegation keeps the longer spoken request, including trailing constraints. Seven regressions cover clarification timing, terminal-only replies, both prefix directions, consecutive scoped/unscoped edits, refused preflight and Stop while awaiting clarification. Consumed raw input is cleared so an empty late delegation cannot repeat it.

Consumed user utterances now retain all pending terminal-event identities (including paraphrases) instead of only the last one; a bounded ledger ends the call before dispatch rather than forgetting identities. A shorter post-fallback delegation is already handled, while a longer request remains eligible. Reconnection transfers pending dialogue and clarification state as well as the task outcome, seeds the new call with that dialogue, and waits for a new-call delegation ID plus the actual reply before dispatch. Eight regressions cover terminal-event order, short late delegations during/after work, pending clarification across both reconnect timings, the ledger bound and a newer constrained utterance surviving an older terminal prefix.

Completed outcomes are retained independently of the running task promise while the call is unavailable or the app is away, so a task finished before reconnection is included in the replacement seed without replay. A matching fresh utterance after completion permits intentional repetition; unrelated speech retains fallback suppression. Voice startup reads the cached/fallback Codex client version synchronously and refreshes GitHub metadata in the background. Nine regressions cover completed success/failure/Stop outcomes, a still-connected background call, explicit repetition, stalled GitHub metadata with absent/stale caches and the replacement call’s session-level speakable packets. Replacement startup sends session.context.append on the speakable stream once the server reports session.started, following the official Codex Frameless Bidi implementation. The voice bar also shows a retained task-ended notice or pending question until new speech arrives, so recovery is visible when the service stays quiet. The audio fixture supplies a continuous silent WebAudio source to keep its synthetic capture clock running after the spoken sample ends.

Fallback suppression now remains across unrelated speech and later tasks; a delegation must match fresh post-result speech to intentionally repeat handled work. Delayed old delegations are rejected before consuming new words, and the retained guards have a 4,096-entry bound. Replacement calls wait through another mobile hidden interval and recheck their owner before starting; concurrent return events share one pending reconnect. Voice renews a prematurely rejected access token through the shared ChatGPT sign-in and retries the same call once, preserving account identity. Twelve regressions cover both stale-delegation orders, the guard bound, resume/End/chat-switch during a second hidden interval, renewal success/failure/sign-out/account changes and the real shared credential store.

Ambiguous empty/prefix delegations after fallback no longer consume fresh speech; the frontend is asked to hand over the full current utterance under a new ID. Exact replies match the current utterance rather than concatenated clarification history, whose context still accompanies the request. Main voice requests now persist optional voiceContext, including an empty array for voice mode; preceding visible speech rows carry voiceContextFor. Edit/regenerate retains that dialogue after restart and cuts/restores the whole group, while page boundaries include its prelude. The version 4 envelope is unchanged, and malformed new fields are rejected by the existing chat-file quarantine path. A valid empty final response now sends its computed fallback on the speakable channel. Fourteen regressions cover ambiguity (including meaningful punctuation/sign differences), clarification, empty responses with/without tools, in-memory/restarted reruns, rollback, empty voice mode and paging; malformed-metadata cases extend file validation.

A matching open user turn now survives a stale terminal event, retaining an intentional repeat after intervening small talk until its delegation. Once fallback guards exist, every delegation needs an exact current utterance; an empty transcript cannot authorize a paraphrased old task or unrelated invented request, and the frontend is told to wait for new user speech instead of retrying. Four regressions cover terminal-before-delegation repeats with/without small talk, stale paraphrases without current speech, and a fresh explicit request accepted afterward.

Delegations accepted without a user transcript now retain bounded ownership of the missing transcript. Matching late fragments are withheld from open/pending steering, including fragmented delivery, acknowledgements, case/sentence-ending variation and an early terminal event. A divergent prefix remains fresh speech with its signs preserved; once an owned sentence is complete, later independent speech and explicit repetition still work. Ownership is bounded with the consumed ledger and released on End. Fourteen regressions verify actual sandbox vault-write counts, both terminal orders, fresh repeats, out-of-order shared prefixes, differing signs, the ownership limit and requests preceded by other dialogue. An unseen request has its own ledger entry, so an earlier context turn’s terminal cannot remove it. Empty input does not establish observation; an observed partial prefix retains its original whitespace and owns its remaining fragments, even if a short acknowledgement closes it before delegation.

SDP offer creation and both description setters now have cancellable 15-second deadlines; timeout, End and late resolution release the microphone and peer without continuing startup. The voice model receives silent active-file context updates on note/canvas changes, after connection and on return; the watcher is removed when the call ends. Fragment merging recognizes explicit acknowledgements instead of every short answer, preserving targets such as “Plan.md.” in delegated context. Ten regressions cover all three SDP waits and cancellation, file/context changes and substantive short English/Chinese answers.

Voice selection consumed at begin is now restored after an AgentLoop-level preflight rejection, without replacing a newer selection. Both local WebRTC diagnostic negotiation steps have the same bounded deadline as call startup, so a hung probe closes its peer and later diagnostics still run. Six regressions cover instruction-read and serialized-budget rejection with original/new selections, and both hung local SDP operations.

A completed owned late transcript now checks subsequent fragments against its actual sentence suffix instead of dropping every fragment without letters or digits. Leading minus/plus signs and slash path prefixes in fresh speech retain their meaning. Three regressions assert the queued and backend request text, and mounted native UI verifies that a separate minus fragment reaches the backend unchanged.

## Validation

866 automated tests, TypeScript, Svelte (zero errors/warnings) and production build pass. Regressions cover duplicate dispatch, held microphone negotiation, late events, sign-out, scoped writes, compaction refusal, clarification batches, stopped tasks, pending permission cancellation and hung call creation without retries.

The production bundle passed 279 native Mac regression checks and 72 mounted voice-UI checks, including actual hold-key/blur behavior, delegated answer rendering, duplicate suppression, ending and a 375px layout. All 1,809 protected existing vault files retained their hashes. These checks use synthetic microphone/WebRTC/provider transport, and do not establish physical-device acceptance. See phase7-qa.json for candidate hashes and later verification.

A synthetic spoken request passed through the real ChatGPT/Codex WebRTC service, triggered delegation, ran one read_document tool on the real selected chat backend, and returned the test note text to chat and the spoken response. No vault write tool ran. A second real-service scenario held the backend completion boundary during reconnection: the original controller remained until the read finished, a replacement WebRTC call connected, and only one read_document call was retained. Real account call creation and WebRTC connectivity were established with a synthetic audio track. The reconnect fixture also injects a clarification about reading another test note into the client transcript: the real replacement service receives the pending question without replaying the first read. Resuming the reply with a new delegation ID is verified with synthetic transport; physical phone acceptance remains open. Physical microphone sampling is not accepted: this Mac enumerated only Splashtop Remote Sound (Virtual), whose getUserMedia request did not return. Physical iOS/Android and Bluetooth are not accepted by the maintainer in this run; the contributor's earlier Android report is attributed separately.

Automatic speech after reconnect is best effort: a complete spoken recovery was observed, but a consecutive run remained silent despite a healthy new connection. The result is retained in chat and the replacement seed, and a mounted UI notice now provides the deterministic recovery indication. This limitation is not reported as stable automatic spoken acceptance. The latest bundle passed foreground speech, retained context and the visible recovery notice. Automatic reconnect speech also completed in the latest run; earlier quiet runs remain evidence that it is not stable. Earlier successful reconnect speech does not establish stable automatic-spoken acceptance.

Current-head CI, Codex review, unresolved threads and the official Community Preview must all finish successfully before this PR is described as merge-ready. Pending scans are not accepted results.

## Dependency assessment

The lockfile is unchanged from main. The full development-tree npm audit reports five affected packages; the production dependency audit reports zero. The high-severity devalue findings are in Svelte's server-only serialization imports, which this client-mounted plugin does not use. The Svelte advisories require SSR/hydratable, attacker-controlled form/name spreading, or svelte:element tag validation; none is used by this component. See [the form-spreading advisory](https://github.com/sveltejs/svelte/security/advisories/GHSA-rcqx-6q8c-2c42) and [the hydratable advisory](https://github.com/sveltejs/svelte/security/advisories/GHSA-f3cj-j4f6-wq85).

The esbuild advisory concerns its development server; the build uses rebuild/watch and never serves it. The moment finding comes through the external Obsidian development API package, not a bundled moment import; this plugin does not call locale with user input. These pre-existing build/unused-path findings are assessed separately from the official production-dependency scan; they are not presented as an all-dependencies-clean result.
